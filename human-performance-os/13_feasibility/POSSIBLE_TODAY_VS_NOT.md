# Feasibility — today vs not yet

## Possible today (build Phase-1)
- Calendar-aware pre-event and gap resets  
- Travel date detection → jet-lag *education* + light timing guidance  
- Sleep duration vs personal baseline → load advice  
- Self-report micro-check-ins  
- Staff console recommendations  
- Protocol metadata + rule engine  
- Notification caps + quiet hours  
- Outcome logging for future personalization  

## Possible with care (Phase-1.5)
- On-device receptivity heuristics (DND, in-call, driving)  
- Preference learning from completions  
- Multi-day travel plans  

## Needs more research / validation
- Reliable real-time “stress” from PPG in daily life  
- Emotion recognition from wearables  
- Fully automatic L8 predictive interventions without annoyance  
- Causal proof that vendor Recovery scores improve outcomes  

## Not realistically solvable soon
- Knowing “exactly how they feel” without asking  
- Replacing therapists / physicians  
- Perfect interruptibility prediction  
- Inferring private life events from weak sensors  

## Biggest unsolved problems
1. **Measurement–construct gap** (sensors ≠ psychological state)  
2. **Annoyance vs benefit tradeoff** under real UHNW intolerance for spam  
3. **Cold start** for each principal  
4. **EA-mediated calendars** and messy real schedules  
5. **Reward hacking** if optimizing engagement  

## Defensible IP / moat ideas (non-legal advice)
- Client-type × moment × protocol decision graphs for UHNW India/Gulf travel circuits  
- Staff-in-the-loop recommendation UX for luxury ops  
- Evaluation harness (MRT-like) for concierge interventions  
- Privacy architecture for multi-stakeholder access (principal / EA / floor staff)  
- **Not** moat: generic box-breathing library
